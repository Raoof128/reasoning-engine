# Beast Mode Implementation Plan: Phases 7-12

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Requires Phases 0-6 merged (`docs/superpowers/plans/2026-10-18-rust-port-phases-0-6.md`). The agent contract from that plan applies unchanged.

**Goal:** Turn the ported engine into the research organism described in `docs/beast-mode-vision-2026.md`, one feature-gated phase at a time, without ever changing a golden vector or a default-build behaviour.

**Architecture:** Each phase adds a Cargo feature (`replay`, `tasks`, `fulltext`, `graph`, `learn`, `fa`, `wasm-adapters`) or extends an existing one. The default build stays stdio + lexical + bundled SQLite.

**Tech Stack additions:** hayagriva 0.10, ed25519-dalek 3.0, nom 8, petgraph 0.8, usearch 2.26, pdfium-render 0.9 / pdf-extract 0.12, linfa 0.8, wasmtime 50 (pre-release), rmcp `task_manager`.

**Ordering rule:** Phase 7 first (decision 5). Phases 8-12 may be reordered, but 10 needs 9's chunk store and 11 needs the data 8-10 produce.

## Phase 7: Trust and reproducibility (`replay` feature)

### Task 1: Recorded HTTP and `replay`

**Files:**
- Create: `crates/re-retrieval/src/recorder.rs`, `crates/re-cli/src/commands/replay.rs`, `crates/re-retrieval/tests/replay.rs`

Steps:

- [ ] `recorder.rs`: a `reqwest` middleware layer that, when a run is in recording mode, stores each response body and status under `runs/<run_id>/http/<sha256 of method+url>.json` with headers filtered through a deny-list (`authorization`, `set-cookie`, `cookie`, `x-api-key`, any header containing `token`).
- [ ] Replay mode: the same layer serves from that directory and fails closed on a miss (`replay_miss` error, non-retryable).
- [ ] `reasoning-engine replay <run_id>`: re-runs the pipeline from `run.json` inputs in replay mode into a temp dir and compares every artifact hash with `attestation.json`.
- [ ] Test: record an offline-mock run, replay it, assert byte-identical artifacts; tamper one recorded body, assert the replay reports the hash mismatch.
- [ ] Commit `feat(replay): record HTTP responses into run packs and replay them offline`.

### Task 2: Signed attestations and Merkle log

**Files:**
- Create: `crates/re-verify/src/signing.rs`, `crates/re-store/src/transparency.rs`, `crates/re-cli/src/commands/verify_runpack.rs` (extend)

Steps:

- [ ] Key at `~/.reasoning-engine/signing.key` (Ed25519, `0600`), generated by `setup` or on first export; public key printed by `reasoning-engine keys show`.
- [ ] `attestation.json`: `signature` = base64 Ed25519 over `run_pack_hash`, `signature_algorithm = "ed25519"`, `public_key` included.
- [ ] `transparency.rs`: append-only `transparency_log(seq, run_id, run_pack_hash, prev_hash, node_hash)` table; `inclusion_proof(run_id)` returns the hash chain.
- [ ] `verify-runpack`: checks artifact hashes, signature against the embedded public key, and (when the DB is reachable) inclusion in the log; exit codes 0/1/2 for ok/tampered/unknown.
- [ ] Commit `feat(attest): sign run packs and record them in a transparency log`.

### Task 3: CSL citations and numeric claim checker

**Files:**
- Create: `crates/re-verify/src/citations.rs`, `crates/re-verify/src/numeric.rs`, `crates/re-verify/tests/{citations,numeric}.rs`, `assets/csl/*.csl`

Steps:

- [ ] Vendor CSL styles for `harvard_au` (Harvard Cite Them Right or AGPS), `vancouver`, `ieee`, `chicago-author-date`, `legal` (AGLC4) under `assets/csl/`; map profile `citation_style` to files.
- [ ] `citations.rs`: build `hayagriva` entries from `EvidenceRecord` (title, authors, year, venue, DOI, URL) and render `references.<style>.md` plus keep `sources.bib` for compatibility.
- [ ] `numeric.rs`: `nom` grammar for integers, decimals, percentages, ranges (`12-15%`, `12 to 15`), confidence intervals (`95% CI 1.2-1.8`), comparatives (`reduced by`, `increased from X to Y`), units (`ms`, `s`, `%`, `x`, `points`); normalise and compare with 2% relative tolerance.
- [ ] Verifier rule: a `quantitative` claim cannot be `supported` unless at least one parsed number from the claim matches a number in the supporting evidence; otherwise cap at `partially_supported` with rationale `numeric value not found in evidence`.
- [ ] Tests: 30 numeric phrases with expected parses; three citation renderings snapshot-tested with `insta`.
- [ ] Commit `feat(verify): render CSL references and enforce numeric consistency`.
- [ ] Open PR `rust/phase-7-trust`. Exit criterion: replay is byte-identical, tampered packs fail, references render in the profile's style.

## Phase 8: Speculative retrieval (`tasks` feature)

### Task 4: Evidence cache and task-backed angle prefetch

**Files:**
- Create: `crates/re-retrieval/src/cache.rs`, `crates/re-mcp/src/tasks.rs`, `crates/re-store/src/ledger.rs`
- Modify: `crates/re-mcp/src/tools/plan_research_angles_tool.rs`, `scholar_search_tool.rs`

Steps:

- [ ] `cache.rs`: SQLite table `evidence_cache(key, source, query_norm, payload, fetched_at, ttl_s)`; key = sha256(source + normalised query + limit); TTL per source (arXiv 6 h, others 24 h).
- [ ] `tasks.rs`: wrap `rmcp::task_manager::TaskManager`; `plan_research_angles_tool` gains `prefetch: bool` (default false for parity) and, when true, spawns one fan-out per angle and returns `CallToolResponse::Task(CreateTaskResult)` plus the angles in `structuredContent`; `tasks/get` reports per-angle progress.
- [ ] `scholar_search_tool` serves from cache when fresh, records `cache_hit` in provenance.
- [ ] `ledger.rs`: per session, credits used (OpenAlex header), bytes fetched, estimated tokens returned (`len/4`); exposed in `get_session_state` and written to provenance at run end.
- [ ] Skill note: add one optional sentence to `skill/deep-research.md` Phase 1 step 5 recommending `prefetch: true` (the only skill edit in Phases 7-12; keep it backwards compatible).
- [ ] Tests with `wiremock`: prefetch of 3 angles completes while a 2 s delayed source is still pending; a later `scholar_search_tool` for angle 2 is a cache hit.
- [ ] Commit `feat(tasks): prefetch evidence for all angles via the MCP tasks extension`.
- [ ] Open PR `rust/phase-8-speculative`.

## Phase 9: Full text and source quality (`fulltext` feature)

### Task 5: Open-access full-text ingestion and chunk store

**Files:**
- Create: `crates/re-retrieval/src/fulltext/{mod,europepmc_xml,pdf}.rs`, `crates/re-verify/src/chunks.rs`

Steps:

- [ ] Resolve full text in order: Europe PMC full-text XML (no PDF needed), then OpenAlex `best_oa_location.pdf_url`; 20 MB cap; stored content-addressed under the models/cache dir.
- [ ] `pdf.rs`: `pdfium-render` when the pdfium library is present, `pdf-extract` fallback; section detection by heading heuristics (`abstract`, `introduction`, `methods`, `results`, `discussion`, `limitations`, `conclusion`).
- [ ] `chunks.rs`: 512-token chunks with section labels into `usearch` (cosine, bge-small) keyed by evidence ID; persisted single file per run and a global index for cross-session reuse.
- [ ] Verifier: NLI tier takes the top 3 chunks instead of the abstract; support found only in `introduction` or `abstract` caps at `partially_supported` with the section named in the rationale.
- [ ] Tests on two committed OA XML documents (Europe PMC, CC-BY) and one small CC-BY PDF.
- [ ] Commit `feat(fulltext): verify claims against open-access full text`.

### Task 6: Source-quality scoring

**Files:**
- Create: `crates/re-retrieval/src/quality.rs`
- Modify: `crates/re-retrieval/src/sources/{europepmc,openalex}.rs`, `crates/re-retrieval/src/aggregate.rs`

Steps:

- [ ] Map Europe PMC `pubTypeList` and OpenAlex `type`, `primary_location.source.type`, `is_retracted`, `open_access.is_oa` into `source_type` values the profiles already name (`systematic_review`, `clinical_guideline`, `preprint`, `peer_reviewed_article`, `technical_report`).
- [ ] Aggregator applies profile `preferred_source_types` (+0.1 fused score) and `weak_source_types` (-0.2); retracted items get `risk_flags += ["retracted"]` and are excluded from `supported`.
- [ ] Tests on fixtures for each mapped type.
- [ ] Commit `feat(retrieval): score sources by profile-aware publication type and retraction status`.
- [ ] Open PR `rust/phase-9-fulltext`. Exit criterion: `bench verify` shows full-text NLI precision on `partially_supported` above abstract-only NLI.

## Phase 10: Evidence graph, adversarial branch, calibration (`graph` feature)

### Task 7: Evidence graph and retraction cascade

**Files:**
- Create: `crates/re-verify/src/graph.rs`, `crates/re-verify/tests/graph.rs`

Steps:

- [ ] Fetch `referenced_works` and `authorships` for each evidence item from OpenAlex (batched, cached); build a `petgraph::Graph` with citation and shared-author edges.
- [ ] `independence_score(claim)` = number of connected components among its supporting evidence; written into each `VerificationRecord.metadata` and the report.
- [ ] Retraction cascade: for each retracted node, any claim whose supporters are all reachable only through it is demoted to `partially_supported`; `cascade.json` lists affected claims and paths.
- [ ] `report.md` gains a Mermaid block per claim with more than one supporter.
- [ ] Tests on a synthetic 6-node graph.
- [ ] Commit `feat(graph): compute corroboration independence and retraction cascades`.

### Task 8: Adversarial branch and negated search

**Files:**
- Create: `crates/re-core/src/planning/negate.rs`
- Modify: `crates/re-core/src/planning.rs`, `crates/re-mcp/src/tools/plan_research_angles_tool.rs`

Steps:

- [ ] `negate.rs`: deterministic templates producing contradiction queries from a claim (`"<X> does not <verb> <Y>"`, `"no effect of <X> on <Y>"`, `"<X> replication failure"`, `"<X> limitations"`), with a small verb table.
- [ ] `plan_research_angles_tool`: for `beam_search` and `forest` strategies, the last angle is `adversarial` with the negated starter questions; golden vectors unaffected because the legacy angle set is returned when `REASONING_ENGINE_ADVERSARIAL != 1`.
- [ ] Verifier: a claim whose contradiction search returns nothing scoring `contradicted` gains `+0.05` confidence (capped at 1.0) and the rationale `survived contradiction search`.
- [ ] Report: `## Counter-view` section listing contradicted or partially supported claims with their strongest contrary evidence.
- [ ] Commit `feat(planning): add adversarial angle with negated contradiction search`.

### Task 9: Conformal calibration and mid-run budget re-estimation

**Files:**
- Create: `crates/re-verify/src/calibration.rs`, `crates/re-core/src/dora/reestimate.rs`

Steps:

- [ ] `calibration.rs`: load `tests/fixtures/verify/labelled_pairs.json` (and any user-labelled file in the data dir), compute nonconformity scores from NLI probabilities, store the 90% quantile in `~/.reasoning-engine/calibration.json`; verifications gain `coverage_level` and `in_prediction_set`.
- [ ] `reestimate.rs`: after the first evaluation round, recompute difficulty from observed kappa, evidence density (results per source) and score spread; `select_next_branches` may raise or lower `budget_remaining_steps` by at most one tier; off unless `REASONING_ENGINE_DORA=directional`.
- [ ] Tests: calibration coverage on a held-out split within 5 points of the target; re-estimation never exceeds the forest tier.
- [ ] Commit `feat(verify): add conformal calibration and mid-run budget re-estimation`.
- [ ] Open PR `rust/phase-10-graph`.

## Phase 11: Learning and living reports (`learn` feature)

### Task 10: Learned PRM prior and cross-session evidence memory

**Files:**
- Create: `crates/re-verify/src/prior.rs`, `crates/re-cli/src/commands/calibrate.rs`, `crates/re-store/src/evidence_memory.rs`

Steps:

- [ ] Training set builder: for every completed session, `(trace embedding, critique embedding, difficulty, depth) -> in_consensus`; `reasoning-engine calibrate` fits a `linfa` logistic regression, writes `prior-v<N>.bin` with metrics, refuses with fewer than 30 sessions.
- [ ] UCB: `q_value` initialised from the prior when a model exists; blend weight `min(1, sessions/200)`; `select_next_branches` reports `prior_disagreement` when the prior and Claude's score differ by more than 0.4, which the skill may treat as a reflexion trigger.
- [ ] `evidence_memory.rs`: every retrieved snippet embedded into a global `usearch` index; `recall_memory_tool` returns prior evidence hits with their last verification status and date.
- [ ] Tests on a synthetic 50-session dataset; prior beats the 0.0 baseline on held-out consensus prediction (log-loss).
- [ ] Commit `feat(learn): train a PRM prior from session history and reuse past evidence`.

### Task 11: Living reports (`watch`)

**Files:**
- Create: `crates/re-cli/src/commands/watch.rs`, `crates/re-verify/src/diff.rs`

Steps:

- [ ] `reasoning-engine watch <run_id> [--every 7d] [--once]`: re-run each claim's evidence search (recording), re-verify, diff statuses and risk flags, write `runs/<run_id>/watch/<date>.diff.md`, exit 3 when anything changed.
- [ ] With `local-host` and `tasks`: expose the diff as a `subscriptions/listen` notification for connected clients.
- [ ] Test: fixture where the second run marks a source retracted; diff reports the cascade.
- [ ] Commit `feat(watch): re-verify run packs on a schedule and report drift`.
- [ ] Open PR `rust/phase-11-learn`.
